# Client Signals

> The PO's continuously updated record of real client feedback, usage data, support issues, and research findings.
> This is the **primary input** for every intent injection.
> The Guardian references this log in gate reviews to evaluate client impact.
>
> Never delete entries — mark resolved ones with a cycle reference.
> The PO reviews this file before writing every cycle intent statement.

## How to Add a Signal

Copy this block and fill it in:

```markdown
## CS-NNN — [Short Signal Title]

**Date:** YYYY-MM-DD
**Source:** [Feedback form / Support ticket / User research / Analytics / Direct client / PO observation]
**Priority:** High / Medium / Low
**Status:** Open / In Progress (Cycle N) / Resolved (Cycle N)

**Signal:**
[What the client said, did, or reported. Be specific — include numbers where available.]

**Context:**
[Why this matters. What behaviour or outcome is this signal about?]

**Success condition:**
[What would need to be true for this signal to be marked resolved?]

**Resolution:**
[Filled in when cycle ships — reference cycle # and measured outcome]
```
